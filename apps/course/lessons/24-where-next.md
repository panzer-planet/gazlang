You've seen the whole of GazLang: the language, the standard library, a web app with a database,
its tests and its deployment. Here is where to go next.

## Read

- The [language reference](https://github.com/panzer-planet/gazlang/blob/master/docs/language.md)
  covers every feature briefly, with the builtins and every library file.
- The GazLang website has a page for each file of the standard library, built from the
  documentation in its source.
- [CLAUDE.md](https://github.com/panzer-planet/gazlang/blob/master/CLAUDE.md) holds the rules of
  the language and the reasons behind each one, if you want to know why something is the way it
  is.

## Read code

A clone of the repository is full of real GazLang:

- `examples/`: a pathfinder, a Brainfuck interpreter, a Markdown converter and a terminal
  dashboard.
- `games/football/`: a football manager for the terminal, with its own tests.
- `apps/todo/` and `apps/course/`: two web apps with accounts and a database. The second is the
  app you are using now.
- `compiler/`: GazLang's compiler, written in GazLang.

## Build something

The language grows by people writing real programs and saying what hurt. When something is
missing, awkward or wrong, the [issues](https://github.com/panzer-planet/gazlang/issues) are the
place to say so; the [roadmap](https://github.com/panzer-planet/gazlang/labels/roadmap) label shows
what is next.

Thanks for taking the course.
